# 踩坑记录

这份笔记按“症状 → 原因 → 修法 → 怎么验证”组织。所有结论来自 2026-11 的一次实际直播，不是纸面设计。

---

## 1. 游戏状态会过期，而且过期得很像真的

**症状**

某天早上，AI 对观众说：“体力只剩十八，雨又不停。” 但游戏里是晴天，体力也不是 18。观众追问“你确定体力只剩十八？”，它又回答“看了三遍，确实是十八”。

**原因**

聊天回路用的“游戏现场”是托管回合开始时缓存的。那一轮跨过了睡觉，摘要是前一天夜里的：雨天、18 体力。聊天层没有“睡觉”这个事件，于是继续把旧摘要当真。

同时，原来的现场有效期设得太长（接近 15 分钟），足够覆盖一整轮长托管。

**修法**

- 现场摘要的聊天有效期缩到 **180 秒**；超时就让聊天回到“不聊农场”的正常模式。
- 监听到 `sleep` / `execute_sleep` 时，立刻写入一个占位摘要：

  ```text
  刚睡醒，新的一天开始了
  ```

  这不是精确状态，但它**不会说错**。下一轮 `get_state` 会把它替换掉。
- 在聊天 prompt 里加一句：

  ```text
  体力和金钱的数字要照抄现场，不要看错、省略或改写成大概。
  ```

- 每次更新摘要都打一行日志：

  ```text
  现场：时间：...，金钱：...，体力：...
  ```

  出问题时先看这行，不要先怀疑模型。

**验证**

- 睡下后看日志是否出现“刚睡醒”占位；
- 等下一轮 `get_state`，确认占位被真实状态替换；
- 第二天早上发一条测试弹幕，检查回复里的体力/天气是否与游戏内一致。

**通用规则**

玩法状态和聊天上下文要分开管理。玩法可以容忍“旧一点”，聊天不能。两者的 TTL 不应该共用一个值。

## 2. 对话框会冻结游戏时间，但 API 看起来像卡死

**症状**

托管回合停在一个矿洞入口，时间一直停在 10:20。`/api/stardew/state` 的 `line` 和 `menu` 看起来没有变化，像是模型挂了。

**原因**

NPC 对话/剧情会暂停游戏时间。模型发起的 `explore_mine` 还在等对话结束，但对话本身不会自己推进。

另外，`/api/stardew/state` 里的 `line`/`menu` 是**回合开始时缓存**的，会落后于真实场景。拿它判断“现在有没有对话”经常误判。

**修法**

- 用 Mod 的 `dialogue` 工具推进或关闭对话，不要干等。
- 真正确认场景，要发一次新的 MCP `get_state`，或者截一张**裁剪到游戏窗口**的图。
- 设计一个 watchdog（本实验尚未实现）：如果检测到对话/菜单持续超过 10 秒，自动发 `dialogue` 或 `close_menu`，然后重新 `get_state`。

**验证**

- 对话出现时，游戏内时钟是否停止；
- 调用 `dialogue` 后，时间是否恢复；
- 新的 `get_state` 是否显示“可以自由行动”。

## 3. 对话框崩溃不是玄学

**症状**

停止托管后，游戏报 `DialogueBox.closeDialogue()` NullReferenceException，UI 层级坏掉，只能杀进程重启。

**原因**

在对话框还开着的时候停止托管 / 断开 MCP 客户端。Mod 的空闲暂停（`McpIdleSeconds`）到点后，动作被中止，正好撞上对话关闭，触发空引用。

**规则**

1. **先关对话，再停托管。**
2. 不要在对话/剧情中杀游戏进程、断 MCP、切 Mod。
3. 重要存档先备份；出问题后重启游戏，不要反复点 UI 试图恢复。
4. 直播前把“对话 watchdog”列进待办，不要依赖人工盯。

**验证**

- 在安全场景（农场、无对话）停止托管，应该干净退出；
- 在对话中停止托管，是已知高危操作，不要拿来测试。

## 4. 动作语音不能直接 `say()`

**症状**

游戏一浇水，AI 就说话，正好盖住观众弹幕的回复；或者一小时内反复说同一句“种子下地，等它发芽”。

**原因**

`say()` 是最高优先级，会抢占正在合成/播放的聊天回复。动作播报本质上不是“主播必须现在说”的话，不应该走这条路。

**修法**

- 新增独立的 `narrate` 队列，优先级排在弹幕、关注之后（低于礼物和醒目留言）。
- 限制：
  - 每轮最多 2 句；
  - 全局间隔 10 秒；
  - 浇水单独 150 秒间隔（浇水太频繁）；
  - 同一动作不连续重复同一句；
  - TTS 关闭、会话未开始、队列暂停时直接跳过。
- 每轮结束的“汇报”也读出来，但允许在动作语音后再排一条，避免被直接丢掉；同样做 5 分钟去重。
- 汇报先清洗再读：去掉 Markdown、去掉“这轮做了：”这种开头、跳过超时/等待占位，最多 80 字，在句号处断开。

**验证**

- 发一条测试弹幕，确认回复先播，动作语音后播；
- 看日志里的 `回复[手动]`，确认是语音队列而不是聊天回复；
- 连续两轮浇水，确认不会每轮都说。

**经验**

静态台词便宜、稳定，但很容易“说错事实”。如果台词里写了“铜矿”“镐子”“鸡”，而这一局没有，观众立刻出戏。优先写**不带事实的反应句**（“一株一株来，别急。”），或者让模型结合现场生成一句。后者更自然，但要花 token，也会增加延迟。

## 5. 字幕显示内部工具，观感会崩

**症状**

屏幕上出现 `Qoder move_to → (65,22)`、`close_menu`、`wait`，观众不知道这是在干嘛。

**原因**

把模型每一步工具调用都当成“进展”推给字幕。对模型是过程，对观众是噪音。

**修法**

- 只显示结果型动作：浇水、收获、开垦、播种、钓鱼、下矿、买卖、送礼、睡觉、照顾动物、做饭、打怪、升级工具、建造等。
- 隐藏：等待、走路、前往、互动、对话、开/关界面、商店点击、整理背包、查询信息、吃东西、使用工具等过程。
- 地点翻成中文；坐标直接删除；长汇报按句拆行；Markdown 去掉。
- 字幕层最多 4 条，旧的先淘汰；动作卡在“进行中”和“结束”用不同的 TTL。

**验证**

- 开 `?demo=1` 看四种卡片；
- 跑一轮真实托管，确认没有坐标和 `wait`；
- 检查长汇报有没有被截断成半句。

## 6. 弹幕和回复分开显示，观众不知道在回谁

**症状**

弹幕卡片 12 秒就消失，AI 回复 8 秒后出现，两条没有关联。观众问“你在回谁”。

**原因**

弹幕和回复是两条独立的 WS 消息，字幕层没有建立配对。

**修法**

- 收到 `reply` 且 `type=danmaku` 时，记一个“待配对回复”（文本 + 时间）。
- 下一条 `speak` 如果文本相同、且在 25 秒内，就把它们合成一组：
  - 一个 `.pair` 容器，上面弹幕、下面回复；
  - 整组显示 30 秒；
  - 配对成功后清掉待配对状态。
- 不要只按时间配对：游戏动作语音也可能紧接着弹幕出现，会把别人的回复抢走。必须**类型 + 文本**都匹配。
- 同一时间只保留一个待配对回复，避免串台。

**验证**

- 用测试事件发一条弹幕，确认出现“弹幕 + 回复”一组；
- 发一条不会触发回复的弹幕，确认它单独显示；
- 在动作语音密集时发弹幕，确认不会被动作语音抢配对。

## 7. 直播窗口、DPI 和截图

**症状**

想截游戏画面确认状态，截出来是 2560×1440，和窗口坐标对不上；窗口也不在 (0,0)。

**原因**

4K 屏幕 + 150% 缩放。DPI-unaware 的截图 API 拿到的是逻辑分辨率，和物理像素不一致；游戏重启后窗口可能重新居中。

**修法**

- 用 Win32 `GetClientRect` 确认客户区，而不是看外框尺寸；
- 用固定客户区 1920×1080、位置 (0,0) 的 helper，游戏重启后重跑；
- 截图只截游戏窗口，不截整个桌面（聊天区、后台、Key 都可能入镜）；
- HUD 通过 Mod 配置关掉（`ShowHud: false`，只在启动时读取）。

**验证**

- `GetClientRect` 返回 1920×1080；
- 截图里没有 HUD、没有桌面、没有聊天软件；
- 字幕层在游戏画面左下角，不挡关键 UI。

## 8. 重启和恢复：别让“默认关闭”骗了你

**症状**

重启 WhaleTalk 后，弹幕没连上、TTS 没启动、托管也没开；以为配置丢了。

**原因**

这是有意的默认值：`auto_connect=false`、`stardew.auto_start=false`、`tts.auto_start=false`。直播工具不应该在重启后自己开始说话。

**恢复顺序**

1. 启动 WhaleTalk，等界面起来；
2. `POST /api/session/start`；
3. `POST /api/bili/connect`；
4. `POST /api/stardew/start`；
5. `POST /api/tts/start`（引擎启动可能要 20–60 秒）。

所有 POST 需要本机的保护头（具体值见应用源码）。不要把这些接口暴露到公网。

**坑**

- one-file exe 的 `/api/quit` 有时日志已经写“已退出”，进程还挂着；确认 PID 后再强制结束。
- 换 exe 前先备份带时间戳的 `.bak`；不要在直播中直接覆盖正在运行的 exe。
- 只改字幕的 CSS/JS 时，可以临时替换运行中 one-file exe 解压目录里的 `web/overlay.html`，刷新浏览器源即可；这是临时手段，持久化仍要重新打包。

## 9. 同时只能有一个“替玩家操作”的 Mod

**症状**

装了两个 AI 玩游戏的 Mod，角色抢操作、状态互相覆盖。

**原因**

两个 Mod 都在替玩家发动作，输入和状态机冲突。

**规则**

- 只启用一个 player-driving Mod；
- 另一个移到 `Mods-disabled/` 作为可逆备份；
- Mod 自带的 F8 AI 和外部 MCP 也不能同时开；
- 换 Mod 后必须重启游戏，不能热插。
