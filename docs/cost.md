# 成本与运行节奏

这套直播有两条 LLM 回路，成本要分开看：

| 回路 | 消耗 | 频率 | 说明 |
| --- | --- | --- | --- |
| 聊天回复 | Qoder credits / 任意 LLM | 每条被放行的弹幕/礼物 | 和不开星露谷时一样，多出来的是一段“现场摘要” |
| 游戏托管 | Qoder credits | 每 45 秒一轮（可配） | 每轮 1 次 `get_state` + 1–3 个动作 + 1 句汇报 |
| TTS | 本机 GPU | 每条要说的话 | GPT-SoVITS 不按 token 计费，但合成有延迟 |

---

## 1. 不要照抄“每小时多少钱”

网上常见的估算通常假设：

- 固定模型、固定价格；
- 每轮固定 token；
- 缓存全部命中；
- 没有超时、没有重试、没有长回合。

实际直播里这四条都会变。正确做法是**用你自己的账号跑一小时，数日志，再看用量面板**。

### 一小时测量法

1. 开播前记下账号的用量/额度；
2. 正常播一小时，保持 45 秒轮间隔；
3. 数日志：

   ```bash
   grep -c "大肥鱼托管：" logs/app.log        # 游戏回合数
   grep -c "回复\[AI+星露谷" logs/app.log     # 带现场摘要的聊天回复数
   grep -c "回复\[手动\]" logs/app.log        # 动作/汇报语音条数
   ```

4. 再看用量面板的差值；
5. 用“差值 ÷ 回合数”得到单轮成本，再乘你想要的每小时回合数。

## 2. 影响成本最大的几个杠杆

| 杠杆 | 影响 | 建议 |
| --- | --- | --- |
| 轮间隔 | 线性影响回合数 | 45 秒是“有动作但不刷屏”的起点；30 秒更勤，60–90 秒更省 |
| `max_turns` | 限制单轮上限 | 36 是上限，不是目标；大多数轮次用不到 |
| 模型 | 单价和速度 | 先 `Fast`；只有复杂规划（社区中心、矿洞路线）再换强模型 |
| 每轮动作数 | 影响回合长度和重试 | ≤3；一次做太多会超时，反而更贵 |
| Prompt 长度 | 输入 token | 只给 200 字以内的现场摘要，不要塞完整背包/地图/日志 |
| 失败重试 | 隐性大头 | “失败一次就换目标”，不要让它对同一个点重试到上限 |
| 聊天注入 | 每条回复的输入 token | 现场摘要 180 秒过期；话题不相关时不要强行注入 |
| 语音 | TTS GPU/时间 | 静态台词可缓存；汇报每轮都不同，不能缓存 |

---

## 3. 游戏回合一小时大概有多少轮

按 45 秒间隔、每轮本身耗时 20–90 秒估算：

- 理想情况：约 40–60 轮/小时；
- 遇到对话、走路、超时：明显下降；
- 一轮做满 36 turns / 600 秒时，这一小时可能只有个位数轮。

所以“每小时成本”波动很大，**先看回合数，再看单价**。

## 4. 静态台词 vs AI 生成台词

| 方案 | 成本 | 自然度 | 风险 |
| --- | --- | --- | --- |
| 固定台词池 | 0 token | 中 | 容易说错事实（铜矿/镐子/鸡）；反复听会腻 |
| 每轮 AI 汇报 | 已包含在游戏回合里 | 高 | 依赖模型状态；偶尔啰嗦 |
| 单独为每个动作生成台词 | 额外 token + 延迟 | 高 | 动作发生时来不及生成，容易和画面对不上 |

本实验的选择：

- **动作瞬间**用固定台词池，只写不带事实的反应句；
- **每轮结束**用模型生成的 40 字汇报，既当字幕也当语音；
- 静态台词按动作分池，同一动作不连续重复；浇水单独降频。

---

## 5. TTS 成本

- GPT-SoVITS 本机运行，按 GPU 时间而不是 token；
- 固定台词可以预合成/缓存，首次之后几乎零延迟；
- 模型生成的汇报每轮不同，必须现场合成；
- 如果 GPU 较弱，合成会排队，听起来像“反应慢半拍”；
- 动作语音是低优先级，宁可晚一点，也不要抢占弹幕回复的合成队列。

---

## 6. 省钱但不降观感的做法

1. 轮间隔从 45 秒调到 60 秒，观众几乎察觉不到；
2. 只在有“结果”时说话，走路/等待不出声；
3. 汇报控制在 40 字以内，TTS 更短、合成更快；
4. 同一动作的静态台词做去重，避免重复；
5. 聊天只在话题相关时提游戏，不要每句都注入；
6. 用 `Fast` 跑日常，复杂任务再切强模型；
7. 超时/做满上限不重试，直接进入下一轮，避免雪崩；
8. 监控日志里的回合数和超时率，异常升高先停下排查，不要让它空烧。

## 7. 另一条路线：Mod 自带 AI

BlindWhaleFarmer 自带一个 F8 的 DeepSeek 驱动模式，和外部 MCP 不能同时开。它省去了自己搭 LLM 调用，但：

- 模型和价格由 Mod 决定；
- 每步输入较大（本实验观察到约 10–14k input tokens/步，具体随版本变化）；
- 无法复用你直播间的聊天模型和人格；
- 不适合“聊天 + 游戏”两条回路分开计费/调参的场景。

本实验选外部 MCP + qodercli，是为了让游戏回路和聊天回路解耦，并且能精确控制每轮的动作数和语音时机。

> 所有价格、额度、模型名称都会变。发布这篇文章时不要把具体单价写死；给出测量方法比给出数字更有用。
